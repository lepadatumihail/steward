## platform-facts

**Nothing in the WebMCP platform broke in the last six days — the API, the Chrome flag, and ChatGPT's default-on site tools all hold — but re-verification surfaced three things the Aug-26 findings got wrong or missed: ChatGPT's browser silently ignores the declarative-form API and iframe-registered tools, in-flight-execution survival on abort only lands in Chrome 153 (Sep 8, after judging), and the Devpost eligibility clause requires WebMCP work committed after Aug 25 11:00am PT.**

### Changed since Aug 26

- NEW CONSTRAINT (contradicts T02 §3 'documented differences vs Chrome: none at the API level'): ChatGPT's built-in browser does NOT support the declarative HTML-form API (`toolname`/`tooldescription`) and does NOT discover tools registered in iframes — same-origin or cross-origin. Source: learn.chatgpt.com/docs/webmcp, corroborated by Search Engine Journal's writeup. Direct impact: T02 §1 floated adding one declarative form as 'a cheap add ... to demonstrate breadth' — that add is invisible on the ChatGPT judging path and would burn effort for zero demo value. Keep everything imperative, and keep every tool registration in the top-level document, not an iframe.
- VERSION-GATED BEHAVIOR MISSED ON AUG 26: Chrome's imperative-api doc states that unregistration not breaking in-flight executions holds 'as of Chrome 153'. Chrome 153 ships 2026-09-08 — five days AFTER the deadline. Corroborated by spec commit 'Preserve in-flight executions after unregistration' (#248, 2026-08-19). T02 §1 quoted the pattern with the comment '// unregisters without breaking in-flight executions' as if it were current behavior. On the Chrome judges will actually run (152 or earlier), `controller.abort()` on wallet-disconnect may cancel an in-flight tool execution — design the disconnect path so an aborted execution fails gracefully rather than leaving Steward's UI half-staged.
- CHROME VERSION LANDSCAPE (T02 framing was correct but understated): Chrome 149 went stable 2026-06-02; current stable is Chrome 152, released 2026-08-25; Chrome 153 arrives 2026-09-08 as the first release on Chrome's new two-week cycle. The '149+' floor is trivially met by any current install — but the flag (or an OT token) is still required, since WebMCP is not on by default until the Chrome 157 ship target.
- SPEC CHANGES LANDED AUG 14–19, AFTER MOST DOCS WERE WRITTEN — they touch `executeTool()`, not `registerTool()`: `executeTool()` now accepts an object instead of a JSON string (#246, 2026-08-17), and `RegisteredTool#inputSchema` changed type from `DOMString` to `object` (#241, 2026-08-14). Chrome's doc still describes the old `executeTool(tool, inputJson, options?)` shape — a live spec/implementation skew. Registration is unaffected, but do not make page-side `executeTool()` self-testing load-bearing in Steward's demo or CI.
- ELIGIBILITY CLAUSE NOT IN T02: the Submission Period runs 2026-08-25 11:00am PT → 2026-09-03 1:00pm PT, and a project that existed before the start must have been 'meaningfully extended using WebMCP after the Submission Period start date', with timestamped commit history distinguishing prior from new work. - WEAKENED CLAIM ON CHATGPT PLAN/MODE GATING: T02 said 'no explicit paid-tier gate is documented'. OpenAI's own wording is narrower than T02 recorded — the docs and the 2026-08-25 changelog both phrase invocation as 'ChatGPT Work and Codex can use tools provided by a website', and help-center material describes Work as available on eligible paid plans.
